# FaceForge · 技术架构文档

> 版本 v0.1 · 2026-07-28

## 一、总体架构

Monorepo,三块 + 共享:

```
face-to-face/
  apps/
    web/                 # Next.js + TS 前端(上传/预览/任务/实时)
  services/
    api/                 # FastAPI 网关:REST + WebSocket,任务队列
    face-engine/         # Python 换脸引擎:封装 FaceFusion / Deep-Live-Cam + 模型管理
  packages/
    shared-types/        # 前后端共享的 TS 类型(由 python schema 生成/对齐)
  docs/                  # 需求/技术/任务拆解/进度
  docker/                # Dockerfile + compose(GPU)
```

- **JS 侧**(apps/web、packages):pnpm + Turborepo,测试 Vitest,lint ESLint,type-check tsc。
- **Python 侧**(services/api、face-engine):uv/pip + pytest + ruff + mypy。
- 两侧独立构建,`docker compose` 编排联调。

## 二、技术选型(依据 2026 调研)

| 场景 | 引擎 | 质量管线 |
|------|------|----------|
| 图片 / 视频换脸 | **FaceFusion 3.7.x**(subprocess/CLI 调用) | 检测对齐(InsightFace)→ 换脸(`hyperswap_1a_256`,可切 `inswapper_128_fp16`)→ face enhancer(CodeFormer/GFPGAN)→ 蒙版贴合→ 放大/色彩匹配 |
| 实时换脸 | **Deep-Live-Cam**(或 inswapper 实时管线) | inswapper + GFPGAN,CUDA/CoreML/DirectML/OpenVINO |

> 换脸模型 `inswapper` 为 InsightFace **非商用**授权;商用切 `hyperswap` 系,逐个核对 license。

## 三、模块职责

### face-engine(Python,核心)
- `engine/facefusion_runner.py`:封装 FaceFusion CLI/headless(图片、视频),参数化质量档位。
- `engine/realtime.py`:实时换脸(Deep-Live-Cam 管线 / 逐帧 inswapper),吃帧吐帧。
- `engine/models.py`:模型下载/校验/缓存(离线复用),启动自检。
- `engine/schemas.py`:入参/出参 pydantic 模型(质量参数、人脸选择等)。
- **对外**:`swap_image()`、`create_video_job()`、`realtime_swap_frame()`;引擎调用可注入 mock,便于单测。

### api(FastAPI 网关)
- REST:`POST /swap/image`、`POST /swap/video`(建任务)、`GET /jobs/{id}`(进度/结果)、模型状态。
- WebSocket:`/ws/realtime`(收摄像头帧、回换脸帧)。
- 任务队列:视频异步(内存队列 MVP → P1 上 Redis/RQ),并发受限。
- 全用 POST + JSON(与 face-engine schema 对齐)。

### web(Next.js)
- 页面:图片换脸、视频换脸(带进度)、实时换脸(webcam)。
- 数据:REST 拉任务、WS 走实时;隐私优先(结果本地预览/下载)。
- UI 规范走仓库 `apple-design → frontend-design`,React/Next 走 `vercel-react → next-best-practices`。

## 四、数据流

- **图片**:web 上传 → api `POST /swap/image` → face-engine 同步换脸 → 返回结果(临时存储/直返 b64)。
- **视频**:web 上传 → api 建 job → 队列消费 → face-engine 逐帧 → 进度回写 → web 轮询/WS 拿进度 → 完成下载。
- **实时**:web webcam 抽帧 → WS 送 api → face-engine `realtime_swap_frame` → WS 回帧 → web 渲染。

## 五、部署
- 目标:NVIDIA CUDA GPU 机器。`docker/` 提供 GPU Dockerfile(装 FaceFusion/Deep-Live-Cam 依赖 + ONNX Runtime/TensorRT)。
- `docker compose up`:api + face-engine(共享模型卷)+ web。模型卷持久化,首启自动下载。

## 六、环境约束(如实标注)
- **本开发沙箱无 GPU** → 无法运行真实换脸推理与模型下载。
- 因此:face-engine 的引擎调用层**以 mock 单测覆盖**(参数编排、schema、任务状态机、模型缓存逻辑),真实推理在 GPU 机器按部署文档验证并留证。
- 凡涉及 GPU 推理的产物,文档明确标「需 GPU 机器验证」,不在沙箱假称跑通。

## 七、质量优先的具体参数(默认)
- 换脸器:`hyperswap_1a_256`;原生 `256x256`;face enhancer:`codeformer` 融合度默认 `30`;默认使用收窄柔化的 `box` 蒙版。`occlusion` 按素材开启,避免胡须等大面积遮挡把目标身份覆盖回来。
- 视频:逐帧 + 增强 + 遮挡蒙版;P1 加时序平滑。
- 实时:优先帧率达标,增强按显存开关。
